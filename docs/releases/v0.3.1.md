Security hardening throughout: adding a phone now offers to install the computer's certificate first, and paired phones, chat folders, file transfers and connections are better protected. Checked with automated tests on macOS and Windows and in the iOS Simulator.

## What's new

- **Two steps in 添加设备** (Add device):
  - Step 1 (recommended) installs the computer's root certificate on the iPhone. Scan the first QR code. On an iPhone without the certificate, Safari first warns about that page; it carries no secret, so you can continue there, and checking the fingerprint is what protects the install.
  - Download the certificate. Before installing it, check under More Details that its SHA-256 matches the one the computer shows. Then install it and turn on full trust for it in Settings › General › About › Certificate Trust Settings. With the certificate installed, Safari checks that it is really talking to your computer.
  - A phone that is already paired installs it from **安装电脑的证书** (Install the computer's certificate) in LanShare's menu on the phone instead, and stays paired.
  - Step 2 is the pairing QR code and 6-digit code, as before. The 2-minute code now starts only at step 2.
  - On a Wi-Fi network you trust you can skip step 1; Safari then warns about the connection, as before.
  - LanShare never tells an iPhone that has the certificate to continue past a certificate warning. If one appears, close the page.
- **Pairing again after 重置证书** (Reset certificate):
  - After a reset, every phone must pair again. The same applies when the computer replaces a damaged or expiring root certificate at startup.
  - Old entries stay in the device list and the conversation list, marked **需要重新配对** (Needs pairing again). Their chat history stays readable on the computer, but nothing can be sent to them.
  - Pairing the phone again adds it as a new device with an empty conversation. The old entry keeps the history until you remove it, and removing it deletes that history.
  - On the iPhone, delete the old certificate (Settings › General › VPN & Device Management), install the new one through step 1 and pair again. The install page warns as it does on a new phone; you can continue there.
  - After pairing, delete the Home Screen icon and add it again from Safari: an icon keeps the login it had when it was added.
- **New root certificates** (on new installs, after a reset, or when one is replaced at startup) are limited to server authentication. A certificate already installed on your phones keeps working.
- **Removing a phone** stops its uploads, downloads and live updates at once, even a transfer that is stuck; **pausing sharing** does the same for every phone. Transfers stopped by a pause stay stopped after sharing resumes.
- **Stalled transfers end**: an upload or download that moves no data for 2 minutes is cancelled. Its temporary file is removed and the space set aside for it is released. A slow but steady transfer is not affected.
- **Chat folders stay private**:
  - The chat folders 收件箱 (Inbox) and 已发送 (Sent) of every shared folder that chat files are saved in stay hidden from phones, also after you share another folder, clear the chats or restart.
  - An earlier shared folder counts if the chat history still lists a file from it, or if it is the shared folder when 0.3.1 first starts. A folder moved or renamed on the computer is no longer recognised.
  - A phone cannot rename or delete a folder that holds them; the computer can.
  - If 收件箱 or 已发送 is a link rather than a plain folder, chat files are refused until it is replaced, and the phone is told why before it sends anything.
- **Renaming while files are in use**: a rename now waits while files are being opened or saved. If that takes more than 3 seconds, it asks you to try again. A long upload or download does not hold up a rename.
- **Pictures sent from the computer's clipboard**: a picture file copied from the shared folder is sent only if phones could already download that file.
- **More files are only shown in their folder** when opened from the computer, like apps and scripts already were: disk images, configuration profiles, certificates and keychains, Shortcuts, screen savers, iOS apps, Java Web Start, server-location and Remote Desktop files, and more Windows script and installer types.
- **Files and attachments are no longer kept in the browser cache**, on the phone or in the desktop window. Copies cached by earlier versions stay until the browser drops them.
- **Long links**: a link with a very long run of punctuation in it no longer freezes the chat.
- **Under the hood**: connections and pairing requests from the network are limited, and the build's GitHub Actions are pinned to exact versions and updated by Dependabot.

The interface is in Simplified Chinese. The [README](https://github.com/DEFY-AN94/LanShare#getting-started) explains how to get started.

## Upgrading from 0.3.0

- Replace the app. Your paired devices, chat history, settings and certificate are kept, and phones do not need to pair again.
- The root certificate already on your phones stays as it is and keeps working. Only a new one, made by 重置证书 (Reset certificate), has the server-only limit, and after a reset every phone pairs again.
- To add the certificate to a phone that is already paired, use **安装电脑的证书** (Install the computer's certificate) in LanShare's menu on the phone. It stays paired.

## Before you install

- **Neither build is signed with a developer certificate** (the Mac app has only an ad-hoc signature).
  - Mac: macOS blocks the first launch. Allow it in System Settings › Privacy & Security › **Open Anyway**. When macOS asks whether LanShare may accept incoming network connections, click **Allow**, or the iPhone cannot connect. It asks again after each update.
  - Windows: SmartScreen shows "Windows protected your PC". Click **More info › Run anyway**. The installer needs administrator rights and adds a firewall rule that allows LanShare only on Private networks and only from the local subnet.
- **The Windows version has been tested only by CI**: unit and API tests, plus an automated silent install, firewall-rule check, start and uninstall. It has not been tested by hand yet. Those checks are listed under "Windows testing, later" in PLAN.md.
- **Not yet tried on a real iPhone or in the installed Mac app**: those checks are listed under "Real iPhone testing, later" in PLAN.md.
- The Mac build is for Apple silicon (arm64) only.
