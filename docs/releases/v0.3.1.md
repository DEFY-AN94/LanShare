Security hardening throughout: adding a phone now starts with installing the computer's certificate, and paired phones, chat folders, file transfers and connections are better protected. Checked with automated tests on macOS and Windows and in the iOS Simulator; it has not been tried on a real iPhone or in the installed Mac app yet.

## What's new

- **添加设备 (Add device) in two steps**:
  - Step 1 (recommended) installs the computer's root certificate on the iPhone. Scan the first QR code, download the certificate, check that its SHA-256 matches the one the computer shows, install it and turn it on under Certificate Trust Settings. With it, Safari checks that it is really talking to your computer.
  - Step 2 is the pairing QR code and 6-digit code, as before. The 2-minute code now starts only at step 2.
  - On a Wi-Fi network you trust you can skip step 1; Safari then warns about the connection, as before.
  - An iPhone that has the certificate is never told to continue past a certificate warning. If one appears, close the page.
- **重置证书 (Reset certificate) now means pairing again**:
  - After a reset, every phone must pair again. So it must when the computer replaces a damaged or expiring root certificate at startup.
  - Old entries stay in the device list marked **需要重新配对** (Pair again). Their chat history stays readable on the computer, but nothing can be sent to them.
  - On the iPhone, delete the old certificate (Settings › General › VPN & Device Management), install the new one through step 1 and pair again. Delete the Home Screen icon too and add it again from Safari: it keeps the login it had when it was added.
- **New root certificates** (new installs and resets) are limited to server authentication. A certificate already installed on your phones keeps working.
- **Removing a phone or pausing sharing** stops its uploads, downloads and live updates at once, also a transfer that is stuck. Transfers that were running when sharing was paused stay stopped after it resumes.
- **Stalled transfers end**: an upload or download that moves no data for 2 minutes is cancelled, and its temporary file and the space set aside for it are released. A slow but steady transfer is not affected.
- **Chat folders stay private**:
  - The chat folders (收件箱 and 已发送) of every shared folder that held chat files stay hidden from phones, also after you share another folder, clear the chats or restart.
  - A phone cannot rename or delete a folder that holds them; the computer can.
  - If 收件箱 or 已发送 is a link rather than a plain folder, chat files are refused until it is replaced, and the phone is told why before it sends anything.
- **Renaming while files are in use**: a phone's rename waits for files that are being opened or saved, and after 3 seconds asks to try again. Uploads and downloads in progress no longer hold up renames.
- **Pictures sent from the computer's clipboard** that come from the shared folder are sent only if phones could download them there anyway.
- **More files are only shown in their folder** when opened from the computer, like apps and scripts already were: disk images, configuration profiles, certificates and keychains, Shortcuts, screen savers, and more Windows script and installer types.
- **Files and attachments are no longer kept in the browser cache**, on the phone or in the desktop window. Copies cached by 0.3.0 stay until the browser drops them.
- **Faster links**: a very long message with links no longer freezes the chat.
- **Under the hood**: limits on connections and on pairing requests from the network, and the build actions pinned to exact versions and updated by Dependabot.

The interface is in Simplified Chinese. The [README](https://github.com/DEFY-AN94/LanShare#getting-started) explains how to get started.

## Upgrading from 0.3.0

- Replace the app. Your paired devices, chat history, settings and certificate are kept, and phones do not need to pair again.
- The root certificate already on your phones stays as it is. It gets the new server-only limit only if you reset it, and then every phone pairs again.

## Before you install

- **Neither build is signed with a developer certificate** (the Mac app has only an ad-hoc signature).
  - Mac: macOS blocks the first launch. Allow it in System Settings › Privacy & Security › **Open Anyway**. When macOS asks whether LanShare may accept incoming network connections, click **Allow**, or the iPhone cannot connect. It asks again after each update.
  - Windows: SmartScreen shows "Windows protected your PC". Click **More info › Run anyway**. The installer needs administrator rights and adds a firewall rule that allows LanShare only on Private networks and only from the local subnet.
- **The Windows version has been tested only by CI**: unit and API tests, plus an automated silent install, firewall-rule check, start and uninstall. It has not been tested by hand yet. Those checks are listed under "Windows testing, later" in PLAN.md, and the checks that need a real iPhone under "Real iPhone testing, later".
- The Mac build is for Apple silicon (arm64) only.
